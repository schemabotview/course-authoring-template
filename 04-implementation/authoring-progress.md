# Authoring progress template

- Status: Not started
- Plan revision: Set when a subject course plan exists

## Course status

Populate from the approved course plan. For each course record section IDs, authoring state, technical verification, visual review, and pending work.

## Section records

Record section ID, authoring state (Scaffold/Drafted/Author-checked/Reviewed), sources checked, technical environment and actual results, visual checks, reviewer/date, and unresolved items as work occurs.

## Continuity notes

Record recurring story entities, terminology, environment assumptions, and decisions needed across sections. No subject-specific choices are preselected.

## Composition decisions (populate per subject)

Record descriptive course/section naming, concept/course header format, master-map vocabulary
if used, scene density, learner-facing link preference, supported icon choices, and known mobile
limits. These choices are not preapproved by the sample. Distinguish shared-package version
constraints or temporary adapters from intended content design.

## Actual check record (populate after running)

For each check record command/tool, date, environment/viewport, outcome, evidence path, failure
and correction where relevant, and remaining limitations. Keep source verification, command
execution, structural/build checks, visual author review, and manual user review distinct.
Do not copy `examples/sample-app/VERIFICATION.md` outcomes into this subject record.
